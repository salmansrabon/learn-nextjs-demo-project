1.2 React and Next.js in This Project

React is the UI library. It gives us components, JSX, props, state, events, and hooks. Next.js is the framework around React. It gives us routing, layout files, development/build commands, and conventions for server and client rendering.

QuestionReact answerNext.js answer
How do we build UI?With components that return JSXThose components live inside route files such as app/page.jsx
How do we create pages?React itself does not define file-based routesA folder with page.jsx becomes a route
How do we share a page shell?React can compose childrenapp/layout.jsx wraps the route tree
How do we handle browser interaction?Use state, effects, refs, context, reducers, and event handlersAdd 'use client' when a route needs those browser-side features

Chapter 2 - React JSX Syntax and Events

These lessons build the basic React mental model: a component is a function, JSX is the markup returned by that function, props pass data in, state changes the UI, and events respond to user actions.

2.1 Creating a Component

Build a reusable component in components/WelcomeCard.jsx, then render it from the route file. The function name starts with a capital letter and returns JSX.

2.2 Using Components with Props

Props are read-only values passed from a parent component to a child component. This lesson passes different values into the same ProfileBadge component.

2.3 Fragments

A React component must return one root value. A Fragment groups sibling elements without adding an unnecessary wrapper element to the DOM.

2.4 JSX Syntax Rules

JSX looks like HTML, but it is JavaScript. Use className, close every tag, use braces for JavaScript expressions, and return one root element.

2.5 Conditional Rendering

JSX does not allow if/else directly inside markup. Use && for optional UI, a ternary for exactly two choices, and null to render nothing.

2.6 Rendering Lists

Use map() to turn an array into JSX. Give every repeated element a stable key so React can track changes correctly.

2.7 Event Handling

Event handlers are functions passed to JSX props such as onClick, onChange, and onSubmit. Form submit handlers usually call preventDefault().

Chapter 3 - Component Lifecycle and Hooks

Hooks let function components remember values, run side effects, navigate, read route params, access DOM nodes, memoize work, share context, and manage related state.

3.1 useState

useState stores data that affects rendering. Calling the setter schedules a re-render with the new value.

3.2 useEffect

useEffect runs side effects after render. The dependency array controls when the effect runs again.

3.3 useRouter

useRouter from next/navigation performs programmatic navigation from a Client Component.

3.4 useParams

Dynamic route folders such as [id] create URL params. useParams() reads those values in a Client Component.

3.5 useRef

useRef can point to a DOM element or hold a mutable value that does not trigger a re-render when it changes.

3.6 useCallback

useCallback memoizes a function reference. It is most useful when passing callbacks to memoized child components.

3.7 useMemo

useMemo memoizes a calculated value. Use it for expensive calculations or derived values that should only recompute when dependencies change.

3.8 useContext

Context shares values through the component tree without passing props through every level. Create the context, provide a value, then consume it.

3.9 useReducer

useReducer keeps related state transitions in one reducer function. It is helpful when many actions update the same state object.

Chapter 5 - React Concepts in This Project

5.1 Props vs State

ConceptMeaningExample
PropsRead-only input from parent to childProfileBadge receives name, role, and status
StateComponent-owned data that can changeuseState examples update counters, form values, and UI flags

5.2 Effects and Dependencies

Effects run after render. Use [] for mount-only work, use dependencies when the effect should react to a value, and return a cleanup function for timers, subscriptions, or listeners.

5.3 Derived Values

A derived value can be calculated from existing state or props. Keep it as a normal calculation first. Reach for useMemo only when recalculation is expensive or reference stability matters.

5.4 Shared State

For a small parent-child relationship, pass props. For app-wide values, use context. The theme lesson shows the complete context pattern.

5.5 Reducer State

When state changes through named actions, a reducer is easier to reason about than many separate setter calls. The reducer lesson keeps the action names and state changes together.

Chapter 6 - Interview Essentials

6.1 Quick Questions

QuestionAnswer
What is a React component?A function that returns JSX and can be reused like a custom tag.
Why must component names start with a capital letter?React treats lowercase JSX tags as built-in HTML elements.
Why use props?Props let a parent configure a child component without duplicating the child code.
Why use state?State stores data that changes over time and should update the UI.
Why use keys in lists?Keys help React identify which list item changed, moved, or was removed.
What does 'use client' do?It marks a file as a Client Component so hooks, events, and browser APIs can run.
What is a dynamic route?A folder like [id] creates a route segment whose value can be read with useParams().
When should you use context?When many components need the same value and passing props through every level becomes awkward.
